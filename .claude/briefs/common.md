## Quality bar
- Every visible string via `useT()` with en AND de (natural German, du-Form); numbers/dates/units via `useFormat()`; respect `settings.units` and `settings.weekStart`. Workout titles via `workoutTitle(w, lang)`; link activities to '/activities/:id'.
- Charts: follow the web conventions + dataviz rules exactly (validated palette via `useChartTheme()`, fixed sport colors via `sportColor()` and `sortSports()` order, ONE y-axis per chart — never dual axis, use a second chart; legend for ≥ 2 series; tooltips; `ChartCard` with a table view; thin marks; text never in series colors; HR zones in `theme.zones`; sequential ramps `theme.seq`/`theme.seqBlue`; status colors only with icon + label). Maps: `BaseMap` + helpers in components/map/layers.ts (add layers in `onStyleLoad`); never many WebGL maps on one page (use `RouteThumbnail`).
- Empty states, loading without layout jumps, errors via `ErrorState`. Responsive at 1024 px and wide screens (`minmax(0,1fr)`, `min-w-0`).
- Server: zod-validate inputs, `HttpError` for errors, efficient SQL (no N+1; records can have tens of millions of rows — always query by type_id + time range), unit tests for non-trivial logic.
- Before finishing: `npm run typecheck`, `npm test -w @cadence/server`, `npm run build` must pass. Then commit in your worktree (`git add -A && git commit -m "<F>: …"`, message ending with `Co-Authored-By: Claude <noreply@anthropic.com>`). Do not push or create branches.
